# V9.2.1 test evidence

> **Historical document.** Written for an earlier version, before the QIE mainnet deployment of 23 Nov 2026. Statements about what has or has not been deployed, which wallets to create and test counts describe that time. Current state: [`FINAL_RELEASE_READINESS.md`](FINAL_RELEASE_READINESS.md).

Everything below was executed on 2026-11-22 against this exact source. Raw output of every step is in [`evidence/`](evidence/). Nothing is carried over from v9.2.

## Environment

- Linux x86_64, Node.js v22.23.5, npm 10.9.9, registry `https://registry.npmjs.org/` (installs used the lockfiles via `npm ci`)
- solc 0.8.39, optimizer on (200 runs), EVM target paris, viaIR off; Hardhat 2 (versions pinned by `package-lock.json`)

## Exact source tested

- Standard run: `FORK_URL=https://rpc1mainnet.qie.digital bash scripts/run-evidence.sh` from a clean copy (no `node_modules`, `artifacts` or `cache`), 2026-11-22 15:08–15:25 UTC.
- `evidence/SOURCE_HASHES.txt`: SHA-256 of all 86 files of the tested tree; hash of that list `80ade6147061400908b51028f4bbc695d2de78a96ba48bca443cec4e6b1eb10d`. **Every code, test, script, config and lockfile in the delivered folder is byte-identical to the tested tree.** Afterwards, this file was added and one number was corrected in `V9_2_1_CHANGELOG.md` (the parity test count).
- Exhaustive run: started separately at 14:04 UTC on the same contracts and tests. `evidence/13-EXHAUSTIVE_SOURCE_HASHES.txt` lists its 19 inputs; all are identical to the final source except `hardhat.config.js`, where the optional `FORK_URL` and `HARDHAT_CHAIN_ID` settings were added afterwards (when neither is set, as in that run, the default network is unchanged).
- No git repository, so no commit hash; the file hashes take its place.

**The 6 pending tests** in the standard suite are the exhaustive tests (3 cover levels × 2 modes), skipped unless `EXHAUSTIVE=1`. They were run separately: see the exhaustive row.

**What the 122 tests include:**
- the earlier scenario, attack, v6 and invariant suites (150 random patterns alternating modes, ledgers checked against the token balance after every call);
- `SavingsCircle.v92.test.js` (10 tests, numbers updated for the new join amount);
- `SavingsCircle.v921.test.js` (8 tests: scenarios A–E with exact numbers, nothing held after the last payment, the deployer's access control and registration, bytecode limits);
- `ModeLifecycle.test.js` (3 tests: 15 situations on the contract in both modes, plus leave and cancel refunds);
- the parity suite (34 tests: 16 named scenarios × 2 modes, one precision test of 12 cases, one test of 160 random scenarios), with rules R1–R3 checked on the contract after every transaction in every one of them.

**Slither (exit code recorded as 255, "findings reported"):** 13 results.
- 11 are unchanged from v9.2:
  - remainder arithmetic in `finalize`/`_shareEqually`, which is exact;
  - zero checks on internal ledgers;
  - at most 12 calls in `recordCircle`, only to circles the factory created;
  - timestamp schedule comparisons, by design.
- 2 are new, `reentrancy-benign` and `reentrancy-events` in `CircleFactory.createCircle`. The factory writes its registry and emits events after calling its deployer. That call goes only to the factory's own immutable `CircleDeployer`, which only creates a `SavingsCircle` with the factory's own token, so no code chosen by a user runs during it.

No linter is configured in the project, so none was run.

**A failed run, reported for completeness:** an earlier evidence run passed `FORK_URL` to every step by mistake, so the standard suite ran against a network copy of mainnet. One test timed out and the run stalled. The script now keeps `FORK_URL` and `EXHAUSTIVE` away from every step except their own. The results above are from the corrected run.
